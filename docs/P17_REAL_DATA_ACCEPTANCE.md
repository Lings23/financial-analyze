# P1.7 真实数据采集与验收方案

状态：**首轮小样本已执行，整项未通过**。本文保留验收规程；实际请求、独立原文对照、数据库回放及判定见[2026-09-30 执行记录](P17_ACCEPTANCE_RUN_20260930.md)。P1.7 对应真实 Provider 凭据/配额联调、历史原始版本验证、质量抽检；Phase 1 整体还需 P1.8/P1.9 各自验收。计划中的真实数据准确率 **≥99.5% 是建议目标**；首轮 35/666 一致保留；[2026-10-01 官方参考扩展](P17_REFERENCE_EXTENSION_20261001.md)当轮增加至75/666一致；后续[行情/持续调用验证](P17_MARKET_AND_QUOTA_20261001.md)去重共450/666在来源精度内一致，并验证24次/分钟54次三表调用。仍不足以证明广泛准确率、最高80或三表跨日稳定性。

## 1. 固定验收对象与口径

先验收已进入统一数据层的 Tushare `market_daily` 与 `financial_income`：日线为未复权，字段是开高低收、成交量（规范化为股）、成交额（规范化为元）；利润表为合并、累计、人民币，字段是营业收入、营业总收入、归母净利润。交易日和报告期是数据所属期间，不是数据公开时刻。其他三源候选接口和 P1.8 数据域另列状态，不混入这两项的准确率分母。

采样之前冻结证券、日期、报告期、字段、来源、精度和允许误差，以及参考原文的选择规则。建议先做 6 只证券的小批试运行，再做正式抽检：覆盖沪深北（北交所须先确认实际接口权限）、主板/创业板/科创板、金融/非金融、新上市、停牌或低流动性样本；覆盖至少一个近期和一个较早的交易窗口、年报及季报，以及一组有更正/重述的报告。无法取到的层单列为未验证，不能悄悄换成容易成功的样本。抽样清单及随机种子在查询前归档，记录排除理由。

比较粒度：日线按 `证券 + 交易日 + 未复权口径 + 字段`；财务按 `证券 + 报告期 + 合并/累计口径 + 披露版本 + 字段`。同一报告期的原始版与修订版是两个样本版本。`null`、未上市、停牌、无成交、接口报错和分页截断分别标记；不得用零或空表代替缺失。

## 2. 采集并封存证据

现有 CLI 可作为首批两域的采集入口；需事先把 `STOCK_RESEARCH_DSN` 指向专用验收库，项目 `.env` 已提供 Tushare Token。以下只展示调用形式，执行结果和快照 ID 仍需以实际运行为准：

```powershell
$env:PYTHONPATH = 'src'
python -m stock_research migrate
python -m stock_research ingest --scope p17-validation --symbol 600000 --exchange SSE --dataset market_daily --start 2024-09-01 --end 2024-09-30 --artifacts .artifacts/p17
python -m stock_research ingest --scope p17-validation --symbol 600000 --exchange SSE --dataset financial_income --start 2024-12-31 --end 2024-12-31 --artifacts .artifacts/p17
```

这些命令只完成现有 Provider 的采集与入库；它们本身不做独立原文比对，也不证明历史 `verified_release`。用每次输出的真实 `snapshot_id` 和捕获时间，再执行带时区 cutoff 的 `query` 及权限回放。

1. 用项目本地 `.env` 中的 Tushare Token，在专用验收 scope 和隔离/持久 PostgreSQL 上逐批 `ingest`。每次请求限定证券和不超过 366 天的窗口，记录 API 名、无密钥参数、请求字段、开始/结束时间（带时区）、业务码、耗时、行数、分页/截断状态、错误类别、调用 ID、代码版本。小批运行记录成功率和限流/权限错误；逐步升至低于实际账号配额的配置速率。用户报告的 80 次/分钟不能当成已验证限额，也无需故意压到拒绝服务。
2. 保存供应商**实际返回的请求字段与值**、响应字段顺序、行数和业务码的去密版本；对内容求 SHA-256，写入只追加 Artifact 和捕获清单。禁止保存 token、Authorization、DSN、敏感响应头或错误原文。Tushare 日线/利润表 Provider v2 已归档请求字段的全部返回行，再筛选期间；包含实际字段顺序、响应/选中行数和带时区起止时间。未知额外字段、服务端消息和请求头不归档；不是完整 HTTP 报文证据。旧 v1 归档仅含筛选行的限制继续保留，不补造旧响应。
3. 独立参考优先使用交易所正式行情记录核对日线；财务使用巨潮/交易所或发行人原始定期报告和更正公告。保存公告编号、原文 URL、PDF/HTML 文件哈希、来源页面显示的发布时间、下载时间、页码/表格/行名、单位及版本关系。巨潮公告索引或第三方转述不能替代原文。AKShare 可以用于发现异常与交叉提示；若它与 Tushare 使用相同上游，不能计为独立真值。
4. 每批封存 `manifest`：scope、采样清单版本、代码提交或代码包哈希、Provider/API 版本、调用 ID、原始证据 Artifact ID、参考原文哈希、数据库快照 ID、捕获/入库时间、对照规则版本。凭据只存本地受控环境，不进入清单或发行包。验收结果必须能按清单重放。

## 3. 自动检查与逐项人工核对

| 检查 | 方法与留痕 | 失败处理 |
| --- | --- | --- |
| 可达性与配额 | 每接口跨日小批采集，统计请求数、成功/空表/权限/超时/限流、时延和日期覆盖；单独确认北交所及更正公告样本权限。 | 错误不计为合法空数据；未取到的层为未验证。 |
| 粒度与覆盖 | 用股票上市/退市时间、交易日历、停牌证据建立预期集合；核对实际行数、主键重复、跨页重复、时间最小/最大值。 | 找出漏页、漏日、混合报表类型；无可靠预期集合时只报告观测覆盖，不能宣称完整。 |
| 字段与逻辑 | 检查字段类型、必需值、单位、空值率、`low ≤ open/close ≤ high`、非负成交量/额、财报期与公告日关系；比较不同日期批次的字段/空值漂移。 | Schema、单位或口径错为阻断项；真实零值与缺失分别核查。 |
| 数值独立核对 | 按冻结样本逐字段追到原文页/行。Tushare 日线 `vol` 以手计、`amount` 以千元计，先换算为股/元再比较；财务保留原文单位与小数精度，按公开报表精度设定差额容忍度。 | 记录原值、规范化值、参考值、差额、原因和复核人；口径不一致不可判成匹配。 |
| 历史版本与 PIT | 收集同一报告期原始公告、更正公告及其各自原文；对每版记录可信发布时间和独立文件哈希。用冻结快照测试公开前、公开后、更正前、更正后的 cutoff，以及不同 scope/Provider 权限。 | 无原版内容或可信发布时间就维持 `observed_at`；不能用今天抓取的修订值和旧 `ann_date` 倒填 `verified_release`。 |
| 不可变与重放 | 同一快照在重启、追加新版本后再次查询，核对记录 ID、Artifact 哈希和结果；错误 scope 和未授权 Provider 必须拒绝。 | 快照变化、未来信息可见、越权或哈希不一致为关键失败。 |

实际对照时先判定证券代码、市场、未复权/复权、报告类型、累计/单季、币种、会计单位和版本一致，再比较数值。官方交易所/公告原文也可能修订；保留所用原文版本。来源冲突进入差异台账，不自动由另一 Provider 覆盖。

## 4. PIT 的可证明范围

- **观察时点证据**：现有 Tushare/AKShare 当前获取的历史值只证明本次 `retrieved_at` 后可用。`available_at = retrieved_at`（或更晚的可信捕获时刻）；此前的 public 查询应不可见。system 查询还必须满足 `ingested_at ≤ cutoff`。该模式可以验收保守 PIT，不代表重建了历史当时真相。
- **历史公开版本证据**：只有取得原版及修订版的不可变原文、各自可信发布日期/时间和版本对应关系，才能对相应版本使用 `verified_release`。若来源只给日期，不能擅自构造日内发布时间；日内 cutoff 应保守处理或判为无法证明。公开时间与系统入库时间分别记录。
- 日期精度实现补充：`verified_release_date` 显式区分仅可信发布日期的资格，`published_at=NULL`，最早次日零点（+08:00）起可见。须冻结具体原文/索引/版本关系及应用批准的资格哈希，不能把普通 ann_date 或今日修订响应自动升级。[300122 两版真实案例](P17_RELEASE_DATE_PIT_20261001.md)通过；精确日内时间、广泛覆盖仍未知，原验收范围不变。
- **验收案例**：至少一组真实原版→更正版的数值差异，在原版公开前/后、更正前/后用带 `+08:00` 偏移的 cutoff 读取；另测入库前后 system 模式、不同租户/Provider 授权、冻结快照追加新版前后。只有真的拿到旧文件内容，才可声称验证了旧版本值。历史回溯样本无法取证时，P1.7 历史版本项维持未通过。

## 5. 判定和交付物

计划目标采用 `准确率 = 合格的预先登记比较单元数 / 可比较单元总数`，按日线/财务、证券板块、时间段、字段分别报告分子、分母、错误、不可比较和排除数；总体值不能掩盖任一关键分层失败。参考原文缺失的样本记为**不可比较**，不能从预登记样本中无痕删除。主键/证券/时间/口径/版本不符、未来泄漏、越权、篡改、来源无血缘均为零容忍关键错误。数值目标按 `PLAN.md` 的建议值 ≥99.5% 报告；正式阈值、误差精度和最低样本量须在抽样前冻结。

若希望以“95% 单侧置信、真实准确率至少 99.5%”解释零错误结果，在独立同分布比较单元的理想假设下至少约 **598** 个零错误样本；按证券或公告聚集的字段并不独立，因此 598 个同一证券/报告字段不能作这个统计保证。没有统计保证要求时，也仍须给出原始分母与分层结果，不只报一个百分比。

交付：去密请求/响应与参考原文的哈希清单、预登记样本、可重放快照 ID、逐项差异台账、覆盖/错误/准确率表、真实修订 PIT 回放记录、执行命令与环境版本、仍未验证的范围。`docs/STATUS.md` 只录入实际执行的结果和日期；离线合成测试单列，不计入真实准确率。
