## 修改及原因

检查已安装 AKShare 1.18.97，三个函数通过共享 `fetch_paginated_data` 获取页面。该助手调用内部重试函数，依赖首批实际行数计算页数，未检查重复证券、总数漂移或后页截断。原来进程硬截止能限制总时长，但不能证明完整分页或精确 HTTP 尝试数。

新增 `akshare_spot.py`，只在隔离 worker 中替换上述共享分页助手，原 AKShare 函数继续负责全部23列的字段映射和数值转换。URL、过滤条件和请求字段保持原函数输入：全 A 股原82节点、创业板/科创板原7节点。没有配置新节点、自动fallback或系统代理变化。

- 每页单次尝试，无助手内部重试；页间1秒间隔；最多100页、10000条、单页2MiB、worker输出16MiB、父进程硬截止最多120秒。首批实际行数作为分页容量，未把请求 `pz=100` 当成必然返回100行。
- 全表必须覆盖源报告总数、每页行数正确、全程总数不变、证券无重复、字段顺序一致；截断、重复、漂移、空首批及缺字段均失败，不保存半表为成功。
- 保留源响应字段顺序。东财自动附带 `f140/f141`，已存一行真实诊断包含两字段；SDK32列解析依赖它们。首个合成SDK回归暴露只投影请求字段导致 `Length mismatch`，修正为保留请求字段及这两个已确认自动字段，三接口全部23列映射复核通过。测试数字均为合成fixture，不代表金融真值。
- 成功后保存请求参数、请求/实际字段顺序、各页原始字段值、日期时间、报告总数、页面数、尝试数；不保存消息、响应头或未知额外字段。页面时间须带时区、顺序正确且不晚于捕获时间。
- 捕获主快照增加源Artifact及 `completion_basis`。每次授权读取重新检查源字节哈希、覆盖及五个核心字段映射；创业板/科创板检查代码板块及源市场。原观察快照不改写，新字段缺失时仍标 `not_verified`。完整分页只证明覆盖该次源报告总数，市场全集和报价新鲜性继续为未验证。
- worker失败仅输出去密的错误类、请求次数、最后HTTP状态和重试数；拒绝不合规则诊断。异常消息、代理地址、凭据和上游正文不进入错误证据。
