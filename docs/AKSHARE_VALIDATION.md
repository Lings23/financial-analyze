## 历史 PIT 核查

### 2026-10-01 实时网络追加诊断

在调用前归档安装版本函数源码哈希、原 API/参数和诊断计划，使用 `pz=1` 小页、单次尝试及连接 3 秒/读取 5 秒上限。不输出系统代理地址或上游错误原文；进程内直连不修改系统代理。

原始计划/结果封存于 `.artifacts/p19_20261001/routes/`、`routes82/` 和 `full_a/`。标准全表捕获为一次逻辑调用；SDK 内部可能重试，已在预登记计划标明，不把它报成一次 HTTP 请求。此次仍没有三项合格全表实时快照，P1.9 保持部分完成。复现脚本为 `scripts/probe_p19_routes.py`（含显式 `--spot-host 82.push2.eastmoney.com` 诊断）与 `scripts/probe_p19_full_a.py`；已存在的封存结果拒绝覆盖。

后续改为原函数使用单次请求的有界分页，保存成功源页并检查总数/重复/截断。三接口当地15:48复测均为ProxyError，每项实际1尝试、0重试，无HTTP响应/完整表。初轮及修正轮失败均保留；119项隔离PostgreSQL回归通过不代表真实行情可达。细节和去网络复核见 [有界分页报告](P19_BOUNDED_PAGINATION_20261001.md)。

以 `2024-09-30` 为历史 cutoff，三张财报的日期字段均不含时区及日内发布时间。本轮同一只股票的当前历史表中，`UPDATE_DATE > NOTICE_DATE` 的行数依次为利润表 48/108、资产负债表 22/105、现金流量表 49/92；`NOTICE_DATE <= 2024-09-30` 且 `UPDATE_DATE > 2024-09-30` 的行数分别是 **4、1、4**。这些日期关系提示历史报告可能有后续更新；未归档当时版本，因此无法判断哪些数值改变，也不能把今天返回的行按旧公告日回填为 2024 年可见版本。

用上轮真实采集的深交所总貌不可变快照（14 行，捕获与入库时间均为 `2026-09-28T08:54:31.907675+00:00`）执行 `AkShareCaptureProvider.read`：`2024-09-30T23:59:59+08:00` 的 public 读取被 `PermissionDenied` 拒绝；`2026-09-28T19:00:00+08:00` 的 public 与 system 均可读取；缺少 AKShare 来源权限被拒绝；错误 scope 无法读取该快照。这个实测只证明**采集后的观察时点可重放、采集前不可见**，不证明 2024 年历史来源版本。

PIT 接入判定：历史日线、指数、行业、名录、新闻和当前财报表仍只能按本次实际捕获时间记 `observed_at`。`NOTICE_DATE`、`UPDATE_DATE`、`公告时间` 可保存为来源元数据；只有取得对应原文、可信的首次公开时间、修订版本链及不可变原始归档并交叉核验后，才可将特定版本标记为 `verified_release`。来源字段的日期精度不足时，须用保守的时区感知边界，不能默认为当日开盘前可见。

## 复现

```powershell
.\.venv\Scripts\python.exe scripts/probe_akshare_candidates.py --timeout 25
$env:PYTHONPATH='src'
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

诊断脚本只用于有界联调，不会把候选接口接入生产数据层，也不会保存来源原始 HTTP 响应。联网结果随代理、上游限流和发布时间变化；本表不作为服务可用性承诺。
